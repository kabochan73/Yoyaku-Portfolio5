# 06. 画面設計

画面ごとに、部品の分け方と、状態（読み込み中・空・エラー・送信中・成功）ごとの表示を決める。

## 1. 共通ルール

### 1.1 状態の出し方

| 状態 | 出し方 |
|---|---|
| 初回の読み込み中 | スケルトン（最終的な形と同じ大きさの灰色の枠）。表示されたときにレイアウトがずれないようにする |
| 別のデータへの切り替え中（週送り・検索語の変更） | 前のデータを出したまま薄くする。データを一瞬消さない |
| 同じデータの取り直し中（定期取得・タブに戻ったとき・操作の後） | 何も出さない。届いたら差し替わる |
| 取得の失敗 | その場所にエラー + 「再読み込み」ボタン。空や「受付外」に見せない |
| データが空 | 空であることを文章で出す（「今後の予約はありません」） |
| 送信中 | 送信ボタンを無効にし、文言を「〜中...」にする |
| 送信の失敗 | 操作した場所のすぐ近くに出す。ダイアログの中の操作なら、ダイアログを閉じずに中に出す |
| 送信の成功 | 結果が画面に反映されること自体を成功の合図にする。設定の保存のように見た目が変わらないものだけ「保存しました」を出す（次に入力を変えたら消す） |

- 取得の失敗を「データが無い」と区別する。カレンダーの取得に失敗したとき、全部の枠を「－」にすると「全部埋まっている / 休み」に見えてしまう
- エラーの文言は `ApiError.message`（サーバーの `message`）をそのまま出す
- 項目ごとのエラー（422 の `errors`）は、その入力欄の下に出す

### 1.2 フォームの読み込み待ち

サーバーの今の値を編集するフォーム（料金・定休日）は、値が届くまで操作させない。

- 値が届くまでフォームの代わりにスケルトンを出し、保存ボタンも出さない。読み込み前に保存すると、空欄が0円として、定休日が「なし」として保存されてしまう
- 値が届いたら `useForm({ values })` で入れる

### 1.3 ダイアログ

- 共通の `Dialog`（[05](05-frontend-design.md#ui-部品)）を使う
- 送信中は Esc・背景クリック・閉じるボタンで閉じられない
- 送信に失敗したら、ダイアログを開いたままエラーを中に出す
- 成功したら閉じる。フォーカスはダイアログを開いたボタンに戻す。そのボタンが消えた・押せなくなった場合は、成功メッセージ（無ければ一覧の見出し）に移す
  - 例: 予約した枠は押せなくなるので「予約しました」のメッセージへ。キャンセルした予約の行は消えるので「予約をキャンセルしました」のメッセージへ
- 閉じるボタンの文言は「戻る」にする。「キャンセル」だと「予約のキャンセル」と紛らわしい

### 1.4 日付・時刻・金額の表記

| 対象 | 表記 | 関数（`lib/format.ts`） |
|---|---|---|
| 日付（長い） | `2026年10月6日（火）` | `formatDateJa` |
| 週の範囲 | `10/5 〜 10/11` | `formatWeekRange` |
| 時刻 | `12:00 〜 14:00` | `formatHourRange` |
| 金額 | `¥8,000` | `formatYen` |

## 2. 見た目

| 項目 | 決めたこと |
|---|---|
| 主色 | 緑（Tailwind の `green-600`、押したとき `green-700`、薄い背景 `green-50`） |
| 文字・枠線・背景 | 灰色（`zinc`）。本文 `zinc-900`、補足 `zinc-500`、枠線 `zinc-200`、ページの背景 `zinc-50` |
| エラー・削除 | 赤（文字 `red-700`、背景 `red-50`、削除ボタン `red-600`） |
| フォント | Noto Sans JP（`next/font/google`） |
| ダークモード | 対応しない（ライトだけ） |

- 色は `globals.css` の `@theme` に名前付きで定義し（`--color-primary` など）、部品からは `bg-primary` のように名前で使う。`green-600` を部品に直接書かない
- フォントは `next/font` の変数を `@theme` の `--font-sans` に入れる。`body` で `font-family` を上書きしない
- ダークモード用の CSS 変数を定義しない。定義すると、部品の色と背景の色が食い違う

## 3. 共通レイアウト

```
app/layout.tsx
├── Header
└── {children}

app/(site)/layout.tsx
├── <main>{children}</main>
└── Footer
```

### Header

| 状態 | 右側の表示 |
|---|---|
| 読み込み中 | ボタン2つ分のスケルトン |
| ゲスト | 「ログイン」「新規登録」 |
| 会員 | 「マイページ」「ログアウト」 |
| 管理者 | 「管理者ページ」「ログアウト」 |
| ユーザーの取得に失敗 | ゲストと同じ表示（ヘッダーでエラーを出しても利用者にはどうしようもない） |

- ログアウト中はボタンを無効にする。成功したら `/` を読み直す。ユーザーを `null` にしないので、セッション切れの見張り（ログイン画面へ移動）とぶつからない

### Footer

施設名・電話番号・受付時間・メールアドレス・住所を `getFacility()` から出す。

## 4. トップ（`/`）

```
page.tsx
└── FacilityProvider
    ├── Hero                       施設名・キャッチコピー・電話・住所・メール
    ├── FacilityInfo               営業時間・料金・定休日・利用時間・貸し出し・支払い
    ├── Suspense（CalendarSkeleton）
    │   └── BookingCalendar
    │       ├── WeekNavigator
    │       ├── SelectionHint
    │       ├── CalendarGrid
    │       │   └── SlotCell × (12 × 7)
    │       └── ReservationConfirmDialog
    └── RulesSection               利用規約（01 §5）
```

- `FacilityInfo` の営業時間・利用時間は `facility.rules` から作る

### 4.1 BookingCalendar の状態

| 状態 | 表示 |
|---|---|
| サーバーで今週を取っている間 | `CalendarSkeleton`（曜日・時刻の見出しと、スケルトンのセル） |
| 今週を表示 | サーバーで取った最新の空き状況 |
| 週送り中 | 前の週のセルを出したまま薄くする。見出しの日付は新しい週に変える |
| 取得の失敗 | グリッドの代わりに「空き状況を取得できませんでした」+「再読み込み」 |
| 60秒ごとの取り直し中 | 何も出さない |

### 4.2 枠の表示

| 状態 | PC | スマホ | 押せるか |
|---|---|---|---|
| `available` | 空き | 空 | ○ |
| 開始に選択中 | 開始 | 空（強調） | ○（押すと解除） |
| 終了候補 | 空き（強調） | 空（強調） | ○ |
| `booked` | 予約済 | ✕ | × |
| `past` / 受付外の日 | － | － | × |

- 枠は `<button>`。押せない枠は `disabled`
- `aria-label` は「10月6日（火）12:00〜13:00 空き」の形

### 4.3 選択中の案内（SelectionHint）

| 状態 | 文言 |
|---|---|
| 未選択 | 開始時刻の枠を選んでください（{min}〜{max}時間） |
| 開始を選択中 | 終了時刻の枠を選んでください。{開始}から{min}〜{max}時間まで選べます |
| 開始を選択中で、終了候補が1つも無い | この時間からは{min}時間以上続けて空いていません。別の枠を選んでください |

- `{min}` `{max}` は `facility.rules` から入れる
- `aria-live="polite"` で読み上げる

### 4.4 選択中にデータが変わったとき

特別な処理はしない。選択は残したまま、表示だけ最新のデータに変わる。

- 開始に選んだ枠が `booked` になった: 終了候補が1つも出なくなり、案内が「別の枠を選んでください」に変わる
- 終了候補の途中が `booked` になった: その先の枠が候補から外れるだけ
- 確認ダイアログを開いた後に埋まった: 送信すると `409 slot_taken` になる（4.6）

`selectSlot` / `canBeEnd` は毎回最新の状態で判定する純粋関数なので、データが変わっても矛盾しない。

### 4.5 週送り

- 「← 前の週」: 今週より前には戻れない（`disabled`）
- 「次の週 →」: `meta.bookable_until` を含む週より先には進めない（`disabled`）
- 週を変えたら選択を解除する

### 4.6 ReservationConfirmDialog

```
予約内容の確認
  日付      2026年10月6日（火）
  時間      12:00 〜 14:00
  利用時間  2時間
  合計料金  ¥8,000
  [エラー]
  [戻る] [予約する / ログインして予約]
```

| 状態 | 表示・動作 |
|---|---|
| 未ログイン | 「予約にはログインが必要です」+「ログインして予約」→ `/login` へ移動（選んだ枠は引き継がない） |
| 送信中 | 「予約中...」。閉じられない |
| 成功 | 閉じて、カレンダーの上に「予約しました。確認メールをお送りしました。」+「マイページで確認」リンク。次に枠を選ぶか週を変えるまで出しておく |
| 422 | ダイアログの中にエラー（例: 開始時刻を過ぎています） |
| 409 `slot_taken` | ダイアログの中に「その時間帯は先に予約されました」。カレンダーを取り直し、「予約する」を押せなくする |
| 409 `already_booked_that_day` | ダイアログの中に「この日はすでにご予約があります（1日1件まで）」+「マイページで確認」リンク |

合計料金は `useFacility()` の単価から計算した見積もり。確定の金額はサーバーが計算する。

## 5. ログイン（`/login`）・会員登録（`/register`）

| 状態 | 表示・動作 |
|---|---|
| 送信中 | 「ログイン中...」「登録中...」 |
| 422（ログイン） | フォームの上に「メールアドレスまたはパスワードが正しくありません。」 |
| 422（登録） | 項目ごと（メールアドレスの重複はメールアドレス欄の下） |
| 429 | フォームの上に「試行回数が多すぎます。しばらくしてからお試しください。」 |
| 成功 | ログイン: 管理者は `/admin`、会員は `/`。会員登録: `/` |

- 入力欄と `<label>` を `htmlFor` で結びつける
- `autocomplete` を付ける: `name`, `email`, `current-password`, `new-password`

## 6. マイページ（`/mypage`）

```
mypage/layout.tsx（会員だけ）
└── page.tsx
    ├── MyReservationList
    │   └── ReservationCard × n
    │       └── CancelDialog
    └── Accordion「プロフィール設定」
        └── ProfileForm
```

### 6.1 MyReservationList

| 状態 | 表示 |
|---|---|
| 読み込み中 | カード2枚分のスケルトン |
| 失敗 | 「予約を取得できませんでした」+「再読み込み」 |
| 空 | 「今後の予約はありません」+「空き状況を見る」（トップのカレンダーへのリンク） |
| あり | 日付・開始時刻の順のカード |

### 6.2 ReservationCard

```
2026年10月6日（火）
12:00 〜 14:00（2時間）
¥8,000
                          [キャンセル]
```

`is_cancellable` が偽ならボタンを出さず、`phase` に応じて「ご利用中」（`in_use`）/「ご利用済み」（`finished`）と表示する。

### 6.3 CancelDialog

```
予約をキャンセルしますか？
  日付 / 時間 / 利用時間 / 料金
  [エラー]
  [戻る] [キャンセルする]
```

| 状態 | 表示・動作 |
|---|---|
| 送信中 | 「キャンセル中...」。閉じられない |
| 成功 | 閉じる。一覧から消え、一覧の上に「予約をキャンセルしました」 |
| 409 `reservation_not_cancellable` | ダイアログの中に「この予約はキャンセルできません（開始済み、またはキャンセル済み）」。一覧を取り直す |

### 6.4 ProfileForm（管理画面と共通）

| 状態 | 表示・動作 |
|---|---|
| 初期値 | 名前・メールアドレスは今の値。パスワード欄は空 |
| 送信中 | 「更新中...」 |
| 422 | 項目ごと（現在のパスワードの誤りは「現在のパスワード」欄の下） |
| 成功 | 「プロフィールを更新しました」。パスワード欄を空に戻す。ヘッダーの表示も変わる |

## 7. 管理画面（`/admin`）

1ページ構成。カレンダーを上に常に出し、設定はアコーディオン（開いたときに初めて中身を読み込む）。

```
admin/layout.tsx（管理者だけ）
└── page.tsx
    ├── AdminCalendar
    │   ├── WeekNavigator
    │   ├── SelectionHint
    │   ├── CalendarGrid（予約済みの枠に予約者名）
    │   ├── AdminReservationDialog       予約の詳細・キャンセル
    │   └── PhoneReservationDialog       電話予約の登録
    ├── Accordion「料金設定」        → PriceForm
    ├── Accordion「定休日設定」      → RegularHolidayForm
    ├── Accordion「臨時休業日」      → HolidayManager
    │                                   ├── HolidayForm
    │                                   ├── HolidayList
    │                                   └── HolidayConflictDialog
    ├── Accordion「会員検索」        → UserSearch
    └── Accordion「プロフィール設定」→ ProfileForm
```

### 7.1 AdminCalendar

データは `/admin/calendar` の1本。ブラウザで取る（SSR しない）。読み込み中・週送り・失敗の表示はトップと同じ（4.1）。

枠の表示（トップとの違いだけ）:

| 状態 | 表示 | 押したとき |
|---|---|---|
| `booked` | 予約者名（電話予約は先頭に ☎） | AdminReservationDialog |
| 受付外の日の `booked` | 予約者名（受付外の色の上に） | AdminReservationDialog |
| 受付外の日の `closed` | － | 何もしない |
| `available` | 空き | 電話予約の開始・終了の選択（トップと同じ操作） |

- 週送り: 前は3か月前の週まで、次は制限なし
- 受付外の日は、見出しに理由を小さく出す（「定休日」「臨時休業」）

### 7.2 AdminReservationDialog

```
予約の詳細
  予約者 / 種別（会員・電話）/ 日付 / 時間 / 料金
  [エラー]
  [戻る] [この予約をキャンセル]
```

| 状態 | 表示・動作 |
|---|---|
| 開始済み（`is_cancellable` が偽） | キャンセルボタンを出さない |
| キャンセル中 | 「キャンセル中...」。閉じられない |
| 成功 | 閉じる。カレンダーから消える |
| 失敗 | ダイアログの中にエラー |

会員の予約では、ボタンの上に「会員にキャンセルのメールが送られます」と小さく出す。電話予約では出さない。

### 7.3 PhoneReservationDialog

```
電話予約の登録
  日付 / 時間 / 利用時間 / 合計料金
  予約者名 [          ]
  [エラー]
  [戻る] [登録する]
```

- 予約者名は必須・255文字以内
- 開いたら予約者名の欄にフォーカス。Enter で送信
- エラーはトップの予約確認ダイアログと同じ（409 `slot_taken` など）

### 7.4 PriceForm

| 状態 | 表示・動作 |
|---|---|
| 読み込み中 | 入力欄2つ分のスケルトン。保存ボタンを出さない（1.2） |
| 失敗 | 「料金を取得できませんでした」+「再読み込み」 |
| 入力 | 平日・土日（円/時間）。0以上の整数。空欄は項目エラー |
| 保存中 | 「保存中...」 |
| 成功 | 「保存しました。トップページにも反映されました」 |

値は `useFacility()` から読み、保存に成功したらレスポンス（更新後の施設情報）で置き換える。

### 7.5 RegularHolidayForm

- 曜日7つのトグルボタン（`aria-pressed`）
- 読み込み中・失敗・保存は PriceForm と同じ
- 保存ボタンの上に「すでに入っている予約はキャンセルされません」を常に出す

### 7.6 HolidayManager

**HolidayForm**: 日付（今日以降。`<input type="date" min={today}>`）+ 理由（任意）+「休業日を追加」

| 結果 | 表示・動作 |
|---|---|
| 201 | フォームを空に戻し、一覧に足す |
| 409 `holiday_has_reservations` | HolidayConflictDialog を開く |
| 409 `holiday_already_exists` | 日付欄の下に「すでに休業日として登録されています」 |
| 422 | 項目ごと |

**HolidayConflictDialog**:

```
この日には予約が2件あります
  休業日にすると、2件の予約をすべてキャンセルし、
  会員の方には施設都合のキャンセルメールを送ります。
  [戻る] [予約をキャンセルして休業日にする]
```

承認したら `cancel_reservations: true` で送り直す。

**HolidayList**: 今日以降の休業日を日付の順に

| 状態 | 表示 |
|---|---|
| 読み込み中 | 行2つ分のスケルトン |
| 空 | 「登録された休業日はありません」 |
| 行 | `2026年10月10日（土）— 設備点検` +「削除」 |

「削除」は確認ダイアログを挟む:「休業日を解除しますか？キャンセルした予約は元に戻りません」

### 7.7 UserSearch

| 状態 | 表示 |
|---|---|
| 未入力 | 「名前またはメールアドレスで検索できます」 |
| 入力中（300ms 待つ） | 何も変えない |
| 検索中 | 前の結果を出したまま薄くする |
| 失敗 | 「検索できませんでした」+「再試行」 |
| 0件 | 「該当する会員はいません」 |
| あり | 名前・メールアドレス・予約件数。20件ちょうどのときは「上位20件を表示しています。条件を絞ってください」 |

## 8. エラーページ

## 9. ページタイトル

| ページ | `<title>` |
|---|---|
| `/` | FUTSAL PARK｜屋内フットサルコートの予約 |
| `/login` | ログイン｜FUTSAL PARK |
| `/register` | 会員登録｜FUTSAL PARK |

## 10. スマホ表示

- カレンダー: 時刻の列は `10:00` だけ（PC は `10:00〜11:00`）。枠は「空 / ✕ / －」の1文字
- 管理カレンダーの予約者名は先頭2文字 +「…」。押せば詳細で全体が見える
- ダイアログは画面幅いっぱい（左右 16px の余白）
- 横スクロールはカレンダーの中だけで起こし、ページ全体は横にはみ出さない
